# 今天你收到 Offer 了吗？ · Got an Offer Yet?

一个面向中国应届毕业生的中英双语求职手记。记录自己的进展，不比较、不催促，也不默认生成演示数据。

## 开始使用

需要 Node.js 22.12+（本环境使用 Node.js 24）和 npm。

```bash
cd /workspace/5003
npm ci
npm run dev -- --port 5173 --strictPort
```

开发服务监听 `0.0.0.0:5173`。本地开发时可在浏览器中打开对应端口。无需账号、后端、数据库、环境变量或 API Key。

**云环境访问说明：** 云端的 5173 端口不是公开网址，当前云环境设置界面不提供网页预览。在自己电脑上运行开发命令，或使用下面的离线网页版；如需可分享的网址，需要单独部署到静态网站托管服务。

### 无需安装开发工具的离线网页版

```bash
npm run build:offline
```

生成 `dist/offer-diary.html`。将这个单独的 HTML 文件下载到电脑，再用 Chrome 或 Edge 双击打开，无需 Node.js、服务器或联网。所有脚本、样式和插画已嵌入文件。

本地文件的存储行为由浏览器决定。请保持文件路径和使用的浏览器不变，并定期导出 JSON 备份；离线文件与云端/本地开发服务不会共享数据。

运行 `npm run test:offline` 可检查单文件构建：在禁用网络、没有服务器的隔离浏览器中，仅提供这个 HTML 文件，验证新增投递、复盘、JSON 导出、语言切换、重启后保存与删除。云端浏览器的管理策略禁止 `file:` 地址，因此此检查不包含用户电脑上直接双击文件的步骤。

### 发布为可访问的网址（GitHub Pages）

执行 `npm run build:pages` 会将可独立运行的生产网页输出到 `docs/index.html`，并生成 `.nojekyll`。页面不依赖根目录资源，因此适用于 GitHub Pages 的仓库子路径。

将项目和 `docs/` 推送到仓库的 `main` 分支后，在仓库 **Settings → Pages** 中选择 **Deploy from a branch → main → /docs → Save**。发布成功后，以 GitHub 显示的实际站点网址为准。后续修改应用时，重新运行 `npm run build:pages` 并提交 `docs/` 更新。

```bash
npm run build    # TypeScript 检查与生产构建，输出至 dist/
npm run preview # 预览生产构建，默认端口 4173
npm test         # Playwright 浏览器端到端测试
```

云环境已有 `/usr/bin/chromium`。测试默认使用它；其他机器可通过 `CHROMIUM_PATH` 指定已安装的 Chromium/Chrome 可执行文件，例如：

```bash
CHROMIUM_PATH=/path/to/chromium npm test
```

运行测试时会自动启动开发服务；端口 5173 已有服务时，本地测试会复用它。若测试失败，`test-results/` 会保存当前运行的错误上下文和 trace。

## 第一版功能

- **我的求职进度**：真实空状态、动态个人概览、四类状态看板与列表视图。
- **投递管理**：新增、编辑、详情、删除确认；9 种状态任意切换；1–5 星意愿；招聘链接、薪资和下一步行动。
- **搜索筛选**：按公司/岗位搜索，按状态、意愿和城市组合筛选；心动机会收集 4–5 星投递。
- **面试复盘**：每家公司可以有多轮独立记录，包含日期、问题与回答、自我评价、私人面试官印象和收获；支持编辑和删除。
- **完整双语**：默认中文；界面、校验、确认、状态和情绪反馈支持英文，用户输入保持原文。
- **情绪反馈**：默认温柔鼓励，可选幽默或关闭；只由新增记录或真实状态变更触发，普通编辑不会重复触发。
- **本地保存与备份**：投递、面试和设置持久化到浏览器；可导出包含全部记录及偏好的 JSON。
- **异常保护**：写入失败时保留旧数据并显示错误；无法解析的数据不会被自动覆盖，可导出原始备份后显式重置。
- **响应式与键盘操作**：移动端导航与表单，原生对话框焦点约束、Escape 关闭、减少动态效果支持。

## 技术与目录

使用 React 19、TypeScript、Vite、Lucide 图标和原生 CSS。没有运行时第三方 API、远程字体、统计追踪或个人数据上传。

```text

  types.ts                      投递、面试、偏好及状态模型
  storage.ts                    本地保存、结构检查与导出
  i18n.ts                       统一中英文字典、标签与情绪文案
  styles.css                    视觉样式与响应式布局
  components/
    ApplicationBoard.tsx        看板、列表与组合筛选
    ApplicationForm.tsx         投递表单与日期/链接校验
    ApplicationDetail.tsx       投递详情、面试历史与摘要
    InterviewForm.tsx           面试复盘表单
    Layout.tsx                  导航、页面标题与公共布局

```

## 验收与本地测试

执行 `npm run build` 和 `npm test`。测试覆盖：

1. 首次空状态、完整英文首页，以及运行时没有第三方网络请求。
2. 创建、编辑、星级、自由切换状态、统计更新与跨刷新/新标签页保存。
3. 多轮面试关联、编辑、删除，以及状态结束后保留历史。
4. 公司/岗位搜索、状态/意愿/城市组合筛选、心动机会与看板/列表切换。
5. 未进面、面试未通过和 Offer 的反馈；普通编辑不重复提示；关闭偏好持久化。
6. 必填字段、未来投递日期、非 HTTP(S) 链接与缺失的下一步行动校验。
7. JSON 备份的真实内容、关联面试删除确认、清空确认及偏好保留。
8. 390px 移动端的导航、表单、详情、英文界面和 Escape 操作。
9. 异常本地数据保护、存储空间不足的失败处理，以及弹窗内的错误可见性。
10. 从看板分组新增时预选对应状态。
11. 首页、投递表单、有数据看板、面试详情和设置的自动可访问性检查。
12. 中英文在 320、375、390、768、1024、1440px 宽度下的页面溢出检查。

手动体验建议：添加一份自己的投递，改成一面，进入详情添加两轮复盘，再切换成 Offer；关闭提示后编辑工作地点，刷新页面，确认历史和设置仍保留。最后导出 JSON 备份。

## 数据与限制

- 本地存储键为 `offer-diary.v1`。数据按网站来源隔离：不同域名或端口之间不共享记录。
- 记录只在当前浏览器/设备中保存，清除站点数据、无痕窗口结束或更换设备可能导致记录不可见。请定期导出备份。
- 第一版支持 JSON 导出，尚未提供备份导入、跨设备同步、多人使用或提醒推送。
- 不在多个已打开的标签页之间实时同步编辑。建议在一个标签页中修改记录，其他标签页刷新后读取最新数据。
- 自动测试使用本环境的 Chromium；没有声称已经验证所有 Safari/Firefox 版本或真实手机设备。
- 项目尚未部署到公网或推送到 GitHub。`dist/` 可由任意静态托管服务发布。

下一步适合优先增加带结构校验的 JSON 备份恢复，然后视真实使用反馈决定是否加入排序与可选的跨设备同步。
